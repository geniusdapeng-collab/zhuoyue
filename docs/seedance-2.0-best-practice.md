## 一、核心问题与解决方案

### 1.1 定妆照未生效

**问题现象**：
- 视频中角色未穿警服（穿了运动装）
- 角色形象与定妆照不一致

**根本原因**：
- 仅上传定妆照不够，Prompt 语义权重更高
- 场景描述（如"健身房""运动"）会覆盖角色服装
- 缺少标志性配饰描述（警帽、警徽、肩章）

**解决方案**：
1. **服装锁定**：在 prompt 中明确写"穿警服的"
2. **外观锚定**：添加"佩戴警帽、警徽、肩章、领花、胸牌"
3. **多定妆照**：上传3-5张多角度定妆照（正面、45度、侧面、特写）

### 1.2 台词未生成或说随机内容

**问题现象**：
- 视频无声
- 台词说随机内容（不是 prompt 中的台词）

**根本原因**：
- 未设置 `generate_audio: true`
- Seedance 默认不生成音频

**解决方案**：
- 有台词时自动设置 `generate_audio: true`
- 台词格式：`【台词】"完整台词内容"`
- 避免竖杠 `|`，使用逗号分隔

## 二、API Payload 正确结构

```json
{
  "model": "003cENDPOINT_STD003e",
  "content": [
    {
      "type": "text",
      "text": "16:9 cinematic | 穿警服的卡通3D女性角色角色A，佩戴警帽警徽肩章，站在健身房中... | 【台词】横纹肌溶解会导致肌肉不适和损伤"
    },
    {
      "type": "image_url",
      "role": "reference_image",
      "image_url": {
        "url": "data:image/png;base64,..."
      }
    }
  ],
  "ratio": "16:9",
  "duration": 5,
  "resolution": "720p",
  "generate_audio": true
}
```

**关键字段**：
- `role: "reference_image"` — 必须指定，否则 API 报错
- `generate_audio: true` — 有台词时必须设置
- `content` 数组中 image 必须在 text 之后（依赖顺序）

## 三、Prompt 编写规范

### 3.1 基本结构
```
[画幅] [风格] | [服装锁定] [角色名]，[外观锚定]，[动作/姿态]，[场景描述] | [台词]
```

### 3.2 服装锁定（必须）
- ✅ `穿警服的角色A`
- ✅ `身穿藏青色警用制服`
- ❌ `角色A`（未锁定服装，场景描述可能覆盖）

### 3.3 外观锚定（建议）
- 警察：`佩戴警帽、警徽、肩章、领花、胸牌`
- 护士：`佩戴护士帽、听诊器、胸牌`
- 医生：`身穿白大褂，佩戴听诊器`

### 3.4 台词格式
- ✅ `【台词】横纹肌溶解会导致肌肉不适和损伤`
- ❌ `【台词】横纹肌溶解|会导致肌肉疼痛和损伤`（含竖杠）
- ❌ `横纹肌溶解会导致肌肉疼痛`（缺少【台词】标记）

### 3.5 引用格式
- ✅ `图片1`（官方规范）
- ❌ `@image1`（不支持）
- ❌ `Image 1`（不支持）

### 3.6 敏感词避免
| 禁用词 | 替换为 |
|--------|--------|
| 痛苦 | 不适 |
| 疼痛 | 不适 |
| 受伤 | 受影响 |
| 死亡 | 严重 |
| 血汗 | 体液 |

## 四、高级技巧（来自外部专家报告）

### 4.1 声音描述（视听一体化）
在 Prompt 中描述环境音、音效、配乐：
```
【音效】心跳声渐强
【环境音】医院走廊背景音
【配乐】紧张悬疑氛围音乐
```

### 4.2 多镜头时间戳
单条 Prompt 规划分镜：
```
[00:00-00:04] 全景，展示城市夜景，镜头缓慢推进
[00:04-00:08] 中景，角色A走入画面，表情严肃
[00:08-00:12] 特写，角色A讲解知识点，手势配合
```

### 4.3 负向提示词
排除不想要的元素：
```
【负向】模糊、变形、多余的肢体、扭曲的面部
```

### 4.4 种子值锁定
批量生成同一角色时，统一设置 seed 值：
```
seed:12345
```
确保微表情、衣纹走向等细节高度一致。

## 五、成本优化策略

### 5.1 预览-定稿工作流
- **创意探索阶段**：使用 `720p` 或 `Seedance 2.0 mini`（成本降低50%）
- **最终定稿阶段**：使用 `1080p` 标准版或 Pro 档

### 5.2 定价参考
- 含视频输入（V2V）：28元/百万Tokens
- 不含视频输入（T2V/图生视频）：46元/百万Tokens
- 利用已有视频参考可降低成本约40%

### 5.3 片段拆分策略
- 生成较短片段（4-5秒）比长片段（10-15秒）单帧质量更高
- 长视频拆分为多个短片段分别生成，后期拼接
- 既能保证质量，又能精细控制每一秒内容

## 六、性能优化与调试

### 6.1 指数退避轮询
```javascript
function pollWithBackoff(jobId, maxWait = 300) {
  const start = Date.now();
  let delay = 3;
  
  while (Date.now() - start < maxWait * 1000) {
    const resp = getJobStatus(jobId);
    if (resp.status === 'completed' || resp.status === 'failed') {
      return resp;
    }
    
    await sleep(delay * 1000);
    delay = Math.min(delay * 1.5, 15); // 指数退避，最大15秒
  }
  
  throw new Error('任务超时');
}
```

### 6.2 限流与并发管理
- 默认有 QPS 和并发数限制（maxConcurrent: 3）
- 收到 429 错误时，实施指数退避重试
- 批量任务采用异步队列，按预设速率平稳发送

### 6.3 常见错误排查

| HTTP状态码 | 含义 | 处理策略 |
|-----------|------|---------|
| 400 | 参数错误 | 检查提示词长度、分辨率、时长等 |
| 401 | 鉴权失败 | 验证 API Key 是否有效、未过期 |
| 429 | 超出速率限制 | 降低频率，实施指数退避重试 |
| 500 | 服务内部错误 | 重试2-3次，或降级到 Fast 档 |
| 503 | 服务暂不可用 | 等待30秒后重试，查看官方公告 |

## 八、视频延长（Extend）

### 8.1 尾帧衔接法
- 以上一段尾帧作为下一段首帧，实现无缝衔接
- 衔接处后期处理：前段末尾删6帧，后段开头删1帧

### 8.2 中性姿态保持
- 每段结尾保持"中性"姿态，为下段提供稳定起始状态
- 避免在段尾做大幅度动作或表情变化

## 九、卓越系统自动化防护

### 9.1 PromptGuardian（自动修复层）
在 `render-request-builder.js` 中自动执行：
1. 服装锁定检测与修复
2. 外观锚定自动添加
3. 引用格式修正
4. 台词净化
5. 敏感词过滤
6. 声音描述检测
7. 多镜头时间戳检测
8. 负向提示词检测
9. 种子值检查

### 9.2 PipelineGuard（强制阻塞层）
在 `render-submitter.js` 中强制检查：
1. REF_IMAGE_ROLE — image_url 必须指定 role
2. GENERATE_AUDIO — 有台词时必须设置 generate_audio
3. REF_IMAGE_COUNT — 建议至少3-5张定妆照
4. COSTUME_LOCK — Prompt 必须锁定服装
5. APPEARANCE_ANCHOR — 建议描述配饰
6. DIALOGUE_FORMAT — 台词不能含竖杠
7. SENSITIVE_WORDS — 不能含敏感词
8. REFERENCE_FORMAT — 不能用 @imageN
9. PROMPT_LENGTH — 不能超过1500字符
10. IMAGE_FILE_VALID — base64数据必须有效
11. MULTIMODAL_LIMIT — 参考素材≤12个
12. RESOLUTION_OPT — 预览提示使用720p/mini
13. NEGATIVE_PROMPT — 提示使用【负向】标记
